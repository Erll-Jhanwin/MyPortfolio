# Data Model

Logical contract shared by SQLite and PostgreSQL adapters. All records private unless noted. IDs are UUID strings generated by the application; all timestamps are UTC ISO-8601.

## Inquiry

`id`, `idempotency_key` (unique), `name` (1–100), `email` (≤254), `inquiry_type` (`project|job|other`), `message` (20–3000), nullable `budget`, nullable `timeline`, exact `consent_wording_version`, `consented_at`, `status` (`new|in_progress|closed|spam`), `created_at`, `updated_at`, `last_meaningful_exchange_at`. Name/email/message are never included in operational logs.

## Notification job

`id`, exactly one of `inquiry_id` or `privacy_request_id` (unique FK with cascade), `status` (`pending|processing|sent|failed`), `attempts`, `next_attempt_at`, `lease_until`, `failure_code` (sanitized short code), `created_at`, `sent_at`. Job holds no duplicate message body and worker selects no visitor contact details; notification email contains only the linked opaque ID and inquiry/request category. Delivery retry backoff is bounded and concurrent workers claim jobs transactionally.

## Privacy request

`id`, unique `idempotency_key`, `email`, `request_type` (`access|correction|deletion`), nullable `details` (bounded), `verification_state` (`pending|verified|rejected`), `status` (`new|in_progress|resolved`), `created_at`, `resolved_at`. Public creation returns neutral 202. No document copies by default.

## Rate limit

`bucket_key` (HMAC digest only, unique), `window_started_at`, `count`, `updated_at`. TTL cleanup removes expired buckets. No plain IP is persisted.

## Content and local preferences

Projects are trusted version-controlled content with slug, type/status, contribution, evidence, limitations, rights and assets. No row-backed CMS. Preference record stays in browser local storage: required=true, optional categories false by default, policy version, saved time; it contains no user identifier.

## Dialect rules

SQLite uses `TEXT` UUID/timestamp, integer booleans/counts, `CHECK`, foreign keys on, busy timeout, WAL. PostgreSQL uses UUID, timestamptz, boolean/integer/checks, matching uniqueness/FKs. Both migrations create indexes and are idempotently tracked. Inquiry and outbox insert share one transaction; unique idempotency and job constraints are enforced in both. PostgreSQL migration revokes public/anon/authenticated privileges for private tables and enables RLS with no anonymous policies. Runtime credentials must be least-privilege; service-role bypass behavior is separately reviewed.
